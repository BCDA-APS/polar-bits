.. py:function:: flyscan_snake(detectors, stepping_motor, stepping_motor_start, stepping_motor_end, stepping_motor_number_of_points, flying_motor, flying_motor_start, flying_motor_end, flying_motor_speed, detector_trigger_period: float = 0.02, detector_collection_time: float = 0.01, file_name_base: str = 'scan', master_file_templates: list = None, md: dict = None, dm_concise: bool = False, dm_wait: bool = False, dm_reporting_period: float = 10 * 60, dm_reporting_time_limit: float = 10**6, nxwriter_warn_missing: bool = False, wf_run: bool = False, wf_settings_file_path: str = None, **wf_kwargs)

   Flyscan using a "snake" trajectory.

   Note the first motor in *args will step and the second will fly (by doing a
   two point step).

   :param detectors: Detectors to trigger during the scan. A single detector is accepted
                     and wrapped in a list; a string raises a TypeError.
   :type detectors: list of ophyd detectors
   :param stepping_motor: Outer-loop motor. It steps through its range while `flying_motor`
                          flies across each row.
   :type stepping_motor: ophyd motor object
   :param stepping_motor_start: Initial position of the stepping motor.
   :type stepping_motor_start: float
   :param stepping_motor_end: Final position of the stepping motor.
   :type stepping_motor_end: float
   :param stepping_motor_number_of_points: Number of points measured along the stepping motor.
   :type stepping_motor_number_of_points: int
   :param flying_motor: Inner-loop motor. It flies between its two ends as a two-point step.
                        Ideally a motor with a custom unstaging that removes "velocity" from
                        the stage_sigs, see ../devices/nanopositioners.py
   :type flying_motor: ophyd motor object
   :param flying_motor_start: Initial position of the flying motor.
   :type flying_motor_start: float
   :param flying_motor_end: Final position of the flying motor.
   :type flying_motor_end: float
   :param flying_motor_speed: Velocity of the flying motor. This will be passed to
                              `flying_motor.velocity` through staging.
   :type flying_motor_speed: float
   :param detector_trigger_period: Time between detector triggers, in seconds. Defaults to 0.02.
   :type detector_trigger_period: float, optional
   :param detector_collection_time: Time the detector spends collecting each image, in seconds. It must
                                    be smaller than or equal to `detector_trigger_period`, otherwise a
                                    ValueError is raised. Defaults to 0.01.
   :type detector_collection_time: float, optional
   :param file_name_base: Base name used for the detector and master file names. Defaults to
                          "scan".
   :type file_name_base: str, optional
   :param master_file_templates: Extra NeXus template entries handed to the master file writer. If
                                 None, an empty list is used.
   :type master_file_templates: list, optional
   :param md: Metadata to be added to the run start.
   :type md: dictionary, optional
   :param dm_concise: Use concise reporting in the APS Data Management workflow. Only has
                      an effect when `wf_run` is True.
   :type dm_concise: boolean, optional
   :param dm_wait: Accepted for API compatibility, but currently unused.
   :type dm_wait: boolean, optional
   :param dm_reporting_period: How often the DM workflow reports progress, in seconds. Only has an
                               effect when `wf_run` is True.
   :type dm_reporting_period: float, optional
   :param dm_reporting_time_limit: How long bluesky keeps reporting on the DM workflow, in seconds. Only
                                   has an effect when `wf_run` is True.
   :type dm_reporting_time_limit: float, optional
   :param nxwriter_warn_missing: If True, the NeXus writer warns about missing content. Defaults to
                                 False.
   :type nxwriter_warn_missing: boolean, optional
   :param wf_run: If True, an APS Data Management workflow is started once the scan
                  files have been uploaded. Defaults to False.
   :type wf_run: boolean, optional
   :param wf_settings_file_path: Path to a YAML file holding the DM workflow kwargs. See
                                 :func:`id4_common.plans.workflow_plan.run_workflow`.
   :type wf_settings_file_path: str, optional
   :param \*\*wf_kwargs: Any remaining keyword arguments are passed to the DM workflow.

   .. seealso:: :func:`bluesky.plan_patterns.outter_product`, :func:`flyscan_cycler`

   Flyscan using a generic path.

   Note that only the last motor will fly (by doing a two point step).

   :param detectors: Currently sort of hardwired for the Eiger, which must be the first item
                     in the list. But this will be removed in the future to match with the
                     POLAR standard of defaulting to our `counters` class.
   :type detectors: list of ophyd detectors
   :param cycler: cycler.Cycler object mapping movable interfaces to positions.
   :type cycler: Cycler
   :param speeds: Velocity of the motors, this is particularly useful for the flying
                  motor. If `None`, then the speed will not be changed. The speed will be
                  passed to `motor.velocity` through staging (see
                  ../devices/nanopositioners.py).
   :type speeds: list
   :param detector_trigger_period: Time between detector triggers, in seconds. Defaults to 0.02.
   :type detector_trigger_period: float, optional
   :param detector_collection_time: Time the detector spends collecting each image, in seconds. It must
                                    be smaller than or equal to `detector_trigger_period`, otherwise a
                                    ValueError is raised. Defaults to 0.01.
   :type detector_collection_time: float, optional
   :param file_name_base: Base name used for the detector and master file names. Defaults to
                          "scan".
   :type file_name_base: str, optional
   :param master_file_templates: Extra NeXus template entries handed to the master file writer. If
                                 None, an empty list is used.
   :type master_file_templates: list, optional
   :param md: Metadata to be added to the run start.
   :type md: dictionary, optional
   :param dm_concise: Use concise reporting in the APS Data Management workflow. Only has
                      an effect when `wf_run` is True.
   :type dm_concise: boolean, optional
   :param dm_wait: Accepted for API compatibility, but currently unused.
   :type dm_wait: boolean, optional
   :param dm_reporting_period: How often the DM workflow reports progress, in seconds. Only has an
                               effect when `wf_run` is True.
   :type dm_reporting_period: float, optional
   :param dm_reporting_time_limit: How long bluesky keeps reporting on the DM workflow, in seconds. Only
                                   has an effect when `wf_run` is True.
   :type dm_reporting_time_limit: float, optional
   :param nxwriter_warn_missing: If True, the NeXus writer warns about missing content. Defaults to
                                 False.
   :type nxwriter_warn_missing: boolean, optional
   :param wf_run: If True, an APS Data Management workflow is started once the scan
                  files have been uploaded. Defaults to False.
   :type wf_run: boolean, optional
   :param wf_settings_file_path: Path to a YAML file holding the DM workflow kwargs. See
                                 :func:`id4_common.plans.workflow_plan.run_workflow`.
   :type wf_settings_file_path: str, optional
   :param \*\*wf_kwargs: Any remaining keyword arguments are passed to the DM workflow.
